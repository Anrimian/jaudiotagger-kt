# jaudiotagger-kt — Kotlin Multiplatform port

Incremental port of jaudiotagger (Java, `../src`) to Kotlin Multiplatform.

## Porting rules

1. **KMP-first**: all logic lives in `commonMain`. Platform specifics go through
   `expect`/`actual` (`FileIo`) or interfaces. Compiling `macosArm64` verifies
   the common code stays JVM-free (linking/running native tests requires a full
   Xcode install).
2. **No reflection**: the ID3 frame body factory (`Class.forName("FrameBody"+id)`
   in `AbstractID3v2Frame`), frame copying (`ID3Tags.copyObject`) and ASF reader
   registration (`ChunkContainerReader.registerChunkReader`) are replaced with
   explicit `when`/`Map<String, () -> T>` factories. R8/ProGuard must be able to
   shrink the library without keep rules.
3. **All I/O goes through `FileIo`** (`io/FileIo.kt`): positioned reads/writes
   plus truncate. Path-based functions are a thin convenience layer. This lets
   Android callers edit MediaStore/SAF files through a `FileDescriptor` without
   temp copies (androidMain actual over `Os.pread/pwrite/ftruncate` — TODO).
4. **Idiomatic API, 1:1 parser/writer logic**: readers and writers are ported
   faithfully, including known quirks (e.g. integer division in the FLAC bitrate
   computation), so behaviour matches the old library on the same files.
5. **Tests run against real files** from `../testdata`; expected values come from
   the original JUnit tests in `../srctest`. Mechanical tables (field enums,
   mappings) are generated by script from the Java sources, never retyped.
6. Logging: none for now (java.util.logging dropped). If needed later — a small
   pluggable callback, no dependencies.

## Recommended order

**The port is complete**: all 13 formats (FLAC, OGG, APE, WavPack, Real, MP3,
DSF, DFF, WAV, AIFF, MP4, WMA), Android/iOS/macOS/JVM targets, publishing.
Possible follow-ups: cross-validate behaviour against the Java library over a
large real-world collection, integrate into the player app, add a
`SamplesSmokeTest`-style corpus runner for regression hunting.

## Known intentional deviations from the Java library

- Ogg writing is in-place instead of temp-file based (MediaStore requirement).
- `readSetupHeaderAndExtraPackets` detects the setup packet position by
  signature; the Java version mis-detected it when the comment ended exactly
  at a page boundary and threw.
- Corrupt samples `test36.ogg`, `test508.ogg` fail with `CannotReadException`
  exactly like the original (covered by `SamplesSmokeTest`).
- Monkey's Audio: the fork's Java reader parsed the APE_HEADER with two uint32
  fields at the front (spec says uint16 compressionLevel + uint16 formatFlags),
  so every offset was shifted and `test000*.ape` failed to read. Ported per
  spec; both samples read and cross-check against their WavPack twins.
- APEv2: the fork mis-derived the item start when the tag has a header
  (`tagStart + 32`), so it could not read back tags it had written. Fixed per
  spec (footer size covers items + footer, never the header).

## Building

The Gradle build lives at the repository root (required for JitPack):

```bash
./gradlew :jaudiotagger-kt:jvmTest                  # compile + run tests on JVM
./gradlew :jaudiotagger-kt:compileKotlinMacosArm64  # verify common code is KMP-clean
./gradlew :jaudiotagger-kt:assembleRelease          # Android AAR
```

Tests read audio samples from `testdata/` (path is passed via the
`TESTDATA_DIR` env var by the build script). JitPack builds are configured in
the root `jitpack.yml` (android + jvm + KMP metadata; Apple targets need a
macOS host).
